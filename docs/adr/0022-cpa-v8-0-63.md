# ADR-0022: CPA-Pin v8.0.63, Header-Baseline gepinnt, kv-store aus

- **Status:** Angenommen
- **Datum:** 2026-11-10
- **Issue:** #4
- **Löst ab:** [ADR-0020](0020-cpa-katalog-overlay.md) (Katalog-Overlay)
- **Ergänzt:** [ADR-0014](0014-cliproxyapi-gepinnt-ohne-kopie.md),
  [ADR-0016](0016-cpa-refresh-barriere.md), [ADR-0017](0017-cpa-egress-nur-anthropic.md)

## Kontext

Der Pin `8ef43e4` kennt `claude-haiku-5-5` und `claude-fable-5-2` nicht; beide kamen über
das Build-Overlay aus ADR-0020 (#137, #3). v8.0.63 (`6db7d4b`) bettet beide ein. Die Prüfung
nach `deploy/cliproxyapi/UPSTREAM.md` ergab:

1. **Claude-Code-Baseline:** Der Default steigt von `claude-cli/2.1.280` auf `2.1.321`
   (`internal/runtime/executor/helps/claude_device_profile.go`). Ein Client darunter, etwa
   Claude Code 2.1.318, gilt nicht mehr als bestätigtes Claude Code; CPA baut dann Betas neu
   und überschreibt User-Agent und Stainless-Header.
2. **kv-store:** neu und standardmäßig an. Er legt `kv.db` (bbolt) ins auth-dir und speichert
   dort Thinking-Replay-, Signatur- und Session-Caches. Das widerspricht der Regel „im
   auth-dir nur die Token-Datei des aktiven Accounts“.
3. **Thinking-Binding:** Für die 5.x-Modelle setzt CPA bei signierten Thinking-Blöcken im
   Verlauf `thinking.block_binding.prefix_mismatch_behavior: "drop_block"` und die Beta
   `thinking-binding-controls-2026-08-01`, auch bei bestätigtem Claude Code, ohne Schalter.
   Claude Code 2.1.318 schickt das selbst nicht. Der Eingriff ist deterministisch und kommt
   ab dem zweiten Request einer Konversation; das kostet einmal pro Konversation einen
   Messages-Cache-Miss, danach ist der Präfix stabil.
4. **Egress:** neu ist ein xAI-Versionscheck gegen `registry.npmjs.org` (Start, dann alle
   3 h, ohne Schalter). Der Egress-Filter aus ADR-0017 verwirft ihn; CPA loggt eine Warnung
   und läuft weiter. `-local-model` verhindert weiter den entfernten Katalog; `/healthz`
   antwortet unverändert.
5. **`replace` im go.mod:** Seit v8.0.55 lenkt Upstream `github.com/MoeForge/moego` auf den
   eigenen Fork `github.com/router-for-me/moego v0.1.2` um (MIT, gleicher Copyright-Inhaber
   wie das Original, Hash in `go.sum`). Damit fällt die Prämisse aus ADR-0014 weg, dass
   `go install …@<commit>` den Stand exakt baut; `go install` lehnt das Modul ab.
6. **Management-API:** Liste, Download, Upload und Delete von `/v8/management/credentials`
   bleiben für tollgate kompatibel. Beide Einfügestellen der Refresh-Barriere existieren
   genau einmal; ihre Tests laufen am neuen Pin.

## Entscheidung

- Pin auf v8.0.63. Overlay, Overlay-Test, `apply.sh`-Zeilen und Dockerfile-Test entfallen.
- `upstream.claude.header-defaults` pinnt die alten Werte (`claude-cli/2.1.280`, `0.112.1`,
  `v26.3.0`). Das Verhalten für Clients bleibt wie am alten Pin.
- `server.kv-store.disabled: true`. Die Caches bleiben wie bisher im RAM.
- Image und `make cpa` bauen in einer temporären Kopie des Moduls (dort greift das
  `replace`), `make cpa` wendet wie das Image die Bridge an. Das ändert ADR-0014 nur im
  Build-Weg; Pin an einer Stelle, keine Kopie im Repo, sumdb-Prüfung bleiben.
- Thinking-Binding und npm-Check werden hingenommen und hier festgehalten; kein Patch, weil
  CPA ungepatcht bleibt (Repo-Regel) und beide deterministisch bzw. folgenlos sind.

## Folgen

- Neue Modelle kommen über Pin-Updates, nicht über eigene Katalog-Einträge.
- Clients unter Claude Code 2.1.280 gelten weiter als nicht bestätigt (wie bisher).
- Jedes Pin-Update prüft Baseline, Header-Logik und neue Body-Eingriffe des
  Claude-Executors zusätzlich zu den bisherigen Punkten (`UPSTREAM.md`).
